# Change Requests (CR) — Template & Log

All deviations from the Project Brief or Architecture must be submitted here as a Change Request. No implementation work that affects architecture, privacy, or security may proceed without an APPROVED CR.

Template
- CR-ID: CR-YYYY-N (auto-assign)
- Requested By: Name / role
- Date: YYYY-MM-DD
- Summary: Short title
- Description: Detailed description of requested change
- Reason: Why change is needed
- Impact: Services, cost, privacy, schedule impacts
- Alternatives considered
- Risk & Mitigations
- Documents affected (list of docs/ files)
- Requested status: NOT APPROVED (default)
- Approver: Project Owner
- Approval date: (filled on approval)

CR Log (initially empty)

- Example placeholder: CR-2026-001 — Change DynamoDB -> Aurora Serverless v2 (NOT APPROVED)

Procedure
- Create CR entry and notify Project Owner.
- Do not implement until CR status = APPROVED and signed-off entries added.
